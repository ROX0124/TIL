## 1. 개발자의 주요 역할

웹 서비스를 개발하는 과정에서는 역할에 따라 여러 분야로 나뉠 수 있다.

### Front-end

사용자에게 직접 보여지는 화면을 담당하는 영역이다.

브라우저나 스마트폰의 UI처럼 사용자가 직접 보고 조작하는 부분을 구현하며, 사용자가 서비스를 직관적으로 이용할 수 있도록 UI/UX를 구성하는 역할을 한다.

사용자가 로그인 버튼을 누르거나 특정 기능을 선택하는 등 서비스와 상호작용하는 부분과 가장 가까운 영역이다.

### Back-end

사용자가 보낸 요청을 실제로 처리하는 영역이다.

프론트엔드에서 전달된 요청을 이해하고, 필요한 로직을 수행한 뒤 데이터베이스와 데이터를 주고받는다.

즉, 사용자의 눈에는 직접 보이지 않지만 서비스가 실제로 동작하도록 만드는 핵심 로직을 담당한다.

### Database

서비스에서 사용하는 데이터를 저장하고 관리하는 영역이다.

사용자 정보, 게시글, 주문 내역처럼 서비스에 필요한 여러 데이터를 보관하고 필요할 때 서버가 데이터를 조회하거나 저장할 수 있도록 한다.

### DevOps

개발뿐 아니라 서비스를 실제 환경에 배포하고 운영하는 영역까지 담당한다.

서비스를 개발하는 것에서 끝나는 것이 아니라 실제 사용자가 안정적으로 서비스를 이용할 수 있도록 운영 환경까지 관리한다.

## 2. 웹 서비스의 기본 구조

웹 서비스의 전체적인 흐름은 다음과 같이 이해할 수 있다.

**사용자 → Front-end → Back-end → Database**

웹 서비스는 크게 사용자 측인 **Client**와 서비스를 제공하는 **Server**로 구분할 수 있다.

- **Client**: 사용자가 직접 사용하는 브라우저나 앱
- **Server**: 사용자의 요청을 받아 처리하는 영역
- **Database**: 서비스에서 사용하는 데이터를 저장하는 공간

사용자는 데이터베이스나 서버에 직접 접근하는 것이 아니라 프론트엔드를 통해 서비스와 상호작용한다.

---

## 3. Request와 Response

웹 서비스의 동작은 기본적으로 **Request(요청)**와 **Response(응답)**의 반복으로 이루어진다.

예를 들어 사용자가 로그인 버튼을 누른다면 다음과 같은 과정이 발생한다.

1. 사용자가 로그인 정보를 입력하고 버튼을 클릭한다.
2. 브라우저 또는 앱이 서버에 요청(Request)을 전달한다.
3. 서버는 전달받은 요청을 확인한다.
4. 필요한 경우 데이터베이스에서 사용자 정보를 조회한다.
5. 서버가 요청을 처리한 결과를 응답(Response)으로 반환한다.
6. 브라우저 또는 앱이 전달받은 결과를 화면에 표시한다.

이를 통해 사용자가 단순히 버튼 하나를 클릭하더라도 실제 서비스 내부에서는 여러 단계의 처리가 이루어진다는 것을 알 수 있었다.

---

## 4. 서비스 처리 과정

오늘 배운 웹 서비스의 기본적인 처리 흐름은 다음과 같다.

### ① 사용자 입력

로그인, 게시물 작성, 검색, 비밀번호 찾기 등 사용자가 원하는 기능을 실행한다.

### ② HTTP Request

브라우저나 앱에서 서버에게 해당 기능을 처리해 달라는 요청을 전달한다.

### ③ Server 처리

서버는 프론트엔드에서 전달받은 요청을 이해하고 필요한 비즈니스 로직을 수행한다.

필요한 경우 데이터베이스에서 정보를 가져오거나 새로운 데이터를 저장한다.

### ④ Response

서버가 처리한 결과를 다시 클라이언트에게 전달한다.

### ⑤ 화면 표시

클라이언트는 서버로부터 받은 결과를 사용자가 확인할 수 있도록 화면에 보여준다.

## 5. 기획자가 알아야 할 개발 개념

개발자가 아니더라도 서비스를 기획하기 위해서는 기본적인 개발 구조를 이해할 필요가 있다.

### Front-end

사용자가 실제로 보는 화면과 관련된 영역이다.

HTML, CSS, JavaScript, React, Vue 등의 기술이 사용되며, 기획자는 이를 UI/UX 설계와 연결하여 생각할 수 있어야 한다.

### Back-end

사용자에게 직접 보이지 않는 서버의 로직을 담당한다.

기획 과정에서는 특정 기능을 구현하기 위해 어떤 데이터가 필요하고, 데이터들이 어떤 관계를 가지고 있는지 생각할 필요가 있다.

### Database

사용자 정보나 게시물, 주문 정보처럼 서비스에 필요한 데이터를 저장한다.

따라서 서비스를 기획할 때도 어떤 정보를 저장해야 하는지를 정의하는 것이 중요하다.

### API

Front-end와 Back-end가 서로 데이터를 주고받기 위한 규칙이다.

기획자는 API 명세서를 통해 개발자와 기능 및 데이터에 대해 소통할 수 있다.

## 💡 새롭게 알게 된 점

기존에는 프론트엔드와 백엔드의 역할을 각각 따로 생각하는 경우가 많았는데, 이번 강의를 통해 하나의 기능이 실행되기 위해 **Client → Front-end → Back-end → Database**가 서로 연결되어 동작한다는 전체적인 흐름을 이해할 수 있었다.

특히 사용자가 버튼 하나를 클릭하는 간단한 행동도 내부에서는 **Request → Server 처리 → Database 접근 → Response → 화면 표시**의 과정을 거친다는 점이 기억에 남았다.

또한 개발자가 아니더라도 서비스를 기획하거나 개발자와 협업하기 위해서는 Front-end, Back-end, Database, API와 같은 기본적인 개념을 알고 있어야 한다는 점을 알게 되었다.
