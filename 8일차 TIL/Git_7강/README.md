# 8일차 - Git 충돌 상황과 병합 중단

## 📌 오늘 학습한 내용

- Git 병합 과정에서 발생하는 충돌 상황
- Merge 진행 중 작업 중단 방법
- Rebase 진행 중 작업 중단 방법

---

## 1. Git 충돌 상황

이번 강의에서는 Git에서 여러 브랜치를 병합하는 과정에서 발생할 수 있는 **충돌(Conflict)** 상황을 실습하였다.

서로 다른 브랜치에서 동일한 부분을 수정한 상태로 병합을 시도하면 Git이 어떤 내용을 적용해야 할지 자동으로 판단하지 못하는 상황이 발생할 수 있다.

이러한 상황을 Git Conflict라고 볼 수 있다.

---

## 2. 병합 과정에서 충돌이 발생한 경우

Merge 또는 Rebase를 진행하는 과정에서 충돌이 발생할 수 있다.

충돌이 발생하면 해당 내용을 확인하고 직접 수정하여 병합을 계속 진행할 수 있지만, 당장 문제를 해결하기 어려운 경우에는 진행 중인 작업을 중단할 수도 있다.

---

## 3. Merge 중단

Merge를 진행하다가 충돌이 발생했고 병합 작업을 계속하기 어려운 경우 다음 명령어를 사용할 수 있다.

```bash
git merge --abort
```

`--abort` 옵션을 사용하면 현재 진행 중인 Merge 작업을 중단할 수 있다.

```text
Merge 진행
    ↓
Conflict 발생
    ↓
당장 해결하기 어려움
    ↓
git merge --abort
    ↓
Merge 작업 중단
```

---

## 4. Rebase 중단

Rebase 과정에서도 충돌이 발생할 수 있다.

Rebase를 계속 진행하기 어려운 경우 다음 명령어를 이용하여 작업을 중단할 수 있다.

```bash
git rebase --abort
```

이를 통해 현재 진행 중인 Rebase 작업을 중단할 수 있다.

```text
Rebase 진행
    ↓
Conflict 발생
    ↓
당장 해결하기 어려움
    ↓
git rebase --abort
    ↓
Rebase 작업 중단
```

---

## 5. Merge와 Rebase 중단 명령어 정리

| 상황 | 명령어 |
| --- | --- |
| Merge 작업 중단 | `git merge --abort` |
| Rebase 작업 중단 | `git rebase --abort` |

두 명령어 모두 병합 과정에서 문제가 발생해 작업을 계속하기 어려울 때 사용할 수 있다.

---

## 💡 새롭게 알게 된 점

이전 강의에서는 `merge`와 `rebase`를 이용하여 서로 다른 브랜치를 합치는 방법을 배웠다면, 이번 강의에서는 실제 병합 과정에서 **충돌이 발생할 수 있다는 점**을 실습을 통해 확인하였다.

특히 충돌이 발생했다고 해서 반드시 그 자리에서 바로 해결해야 하는 것은 아니며, 상황에 따라 `git merge --abort` 또는 `git rebase --abort`를 이용하여 진행 중인 작업을 중단할 수 있다는 점을 알게 되었다.

즉, 병합 과정에서는 단순히 브랜치를 합치는 방법뿐만 아니라 문제가 발생했을 때 안전하게 작업을 중단하는 방법도 알아두는 것이 중요하다고 느꼈다.
